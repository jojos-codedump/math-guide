Computer Networking → CCNA Track
How data moves across wires — the entire internet in one mental model
sequential

You will touch servers, deploy to cloud, debug latency issues, and configure Docker networks every single day. Without knowing IP addressing, DNS, TCP/IP, and HTTP deeply, you're guessing. CCNA level is the target — you don't need to sit the exam, but understand everything it covers.

OSI / TCP-IP model IP addressing / CIDR DNS / DHCP / ARP TCP vs UDP HTTP/1.1 · HTTP/2 · HTTP/3 TLS / HTTPS Routing basics Firewalls / NAT

Backend Engineering

3.1
Node.js
JavaScript on the server — the event loop, streams, and the module ecosystem
sequential

Node isn't just "JS on the server." It's a different runtime environment with a different event loop, filesystem access, streams, and module system. Understand the libuv thread pool, worker threads, and when Node's single-thread model becomes a bottleneck. This is the foundation for Express, Nest, and all Node tooling.

Node event loop (phases, libuv) Streams (readable, writable, transform) fs / path / os / events modules Worker threads Cluster module CommonJS vs ESM in Node Error handling (domains, uncaughtException)

3.2
Express.js → Fastify → NestJS
Learn the minimal framework before the full framework — understand what each adds
sequential within

Express is minimal and shows you the raw HTTP abstraction. Fastify is a modern, typed, faster alternative. NestJS is the opinionated enterprise framework (Angular-inspired, decorator-based) used in large codebases. Learn in order — each one makes the next one comprehensible. Don't start with Nest.

Express middleware pipeline Routing (static, dynamic, nested) Request/Response lifecycle Fastify schema validation Fastify plugins NestJS modules / controllers / services NestJS decorators & DI NestJS pipes / guards / interceptors

3.3
tRPC
End-to-end type safety between your TypeScript backend and frontend
sequential

tRPC removes the client–server contract problem entirely: you define procedures on the server, and TypeScript automatically infers the correct types on the client — no code generation, no Swagger, no manual type sync. Pairs with Next.js and Nest. Requires TypeScript fluency (2.1) and either Express or Nest (3.2).

Procedures (query / mutation) Input validation (Zod) Context & middleware React Query integration Error handling (TRPCError)

4
Databases & Persistence
Learn relational first — SQL fundamentals transfer everywhere. NoSQL comes after. Redis is a specialization. Prisma (ORM) pairs with PostgreSQL. All of these can be learned in parallel with Phase 3.
⬆ Requires: Phase 0 complete. Parallel with Phase 3.
4.1
PostgreSQL
The gold standard relational database — learn this as your primary DB
parallel w/ 4.2

PostgreSQL is the most powerful open-source relational database. Learn SQL properly: joins, window functions, CTEs, indexes, query planning. Understand ACID guarantees and when they matter. PostGIS, full-text search, JSONB columns — Postgres does more than you think.

DDL / DML / DCL Joins (inner, outer, cross) Window functions CTEs & recursive queries Indexes (B-tree, partial, composite) EXPLAIN ANALYZE Transactions & isolation levels JSONB columns
📖 Book
Learning SQL — Alan Beaulieu (O'Reilly)
Concise and complete. pgexercises.com for hands-on SQL drills after.
4.2
MySQL
Widely deployed — important for reading legacy codebases and interviews
parallel w/ 4.1

MySQL differs from PostgreSQL mainly in storage engines (InnoDB vs MyISAM), locking behavior, and some SQL dialect differences. If you master PostgreSQL first, MySQL is a small delta. Many companies (Meta, Airbnb originally) use MySQL at scale — it's essential job knowledge.

InnoDB storage engine MySQL vs Postgres SQL dialect diffs Replication basics MySQL workbench
📖 Resource
MySQL Documentation + SQLZoo (practice)
After Postgres, MySQL docs + SQLZoo are sufficient. Same SQL fundamentals.
4.3
Prisma ORM
Type-safe database access — the modern Node.js ORM
after 4.1

Prisma generates a fully typed client from your schema — you get autocomplete on every query and TypeScript errors if you query columns that don't exist. Prisma Migrate manages your schema evolution. Use it with PostgreSQL in all Node.js projects going forward.

schema.prisma (models, relations) Prisma Migrate Prisma Client (CRUD, relations, aggregates) Raw SQL fallback ($queryRaw) Prisma Studio

prisma.io/docs — Data Modeling + Client sections

MongoDB + Firebase & Supabase
Document database + BaaS platforms for rapid development
after 4.1–4.2

MongoDB is the canonical NoSQL document database. Understand when document modeling is better than relational (flexible schema, nested data, horizontal scale). Firebase Realtime DB + Firestore are BaaS options you're already using. Supabase is "open-source Firebase built on PostgreSQL" — bridging both worlds.

BSON document model Aggregation pipeline Indexes in MongoDB Mongoose ODM Firebase Firestore (rules, real-time listeners) Supabase (Auth, Storage, Realtime)

APIs, Auth & Real-time
The contract between frontend and backend. JWT → GraphQL → WebSockets → Swagger build sequentially. Zod ties back to TypeScript and validates the data boundary end-to-end.

JWT & OAuth2 — Auth0, Firebase Auth, Passport.js
Authentication and authorization — the security boundary of every app
sequential

Authentication is where most security vulnerabilities live. Understand the full auth flow: session-based vs token-based, JWT structure (header.payload.signature), OAuth2 grant types, and why you shouldn't build auth from scratch (use Auth0 or Firebase Auth for production). Passport.js is the Node middleware that glues strategies together.

JWT (sign, verify, refresh tokens) OAuth2 flows (authorization code, PKCE) OIDC (OpenID Connect) Passport.js strategies Auth0 / Firebase Auth integration RBAC (roles & permissions) Secure cookie handling CSRF protection

5.2
GraphQL — Apollo Server & Client
Query exactly what you need — no over-fetching, no under-fetching
sequential

GraphQL is the API design language used at Facebook, GitHub, Shopify, and Airbnb. It solves REST's over-fetching problem by letting clients specify exactly what fields they need. Apollo Server (NestJS-compatible) and Apollo Client (React) are the dominant ecosystem. Understand N+1 query problem and DataLoader to solve it.

SDL (Schema Definition Language) Queries / Mutations / Subscriptions Resolvers DataLoader (N+1 batching) Apollo Client (cache, reactive vars) Code-first vs Schema-first Persisted queries

WebSockets — Socket.io
Persistent bidirectional connections for real-time features
sequential

HTTP is request-response. WebSockets are persistent connections — the server can push data to clients at any time. Socket.io adds namespaces, rooms, reconnection logic, and fallbacks. Essential for chat, live notifications, collaborative editing, real-time dashboards, and multiplayer features.

WebSocket protocol (handshake, frames) Socket.io rooms & namespaces Event-based architecture Scaling WebSockets with Redis adapter Reconnection & heartbeat Server-Sent Events (SSE) vs WebSockets

5.4
Swagger / OpenAPI
Document your API so consumers don't have to guess
parallel w/ 5.5

OpenAPI is the industry standard for REST API documentation. NestJS generates Swagger UI automatically from decorators — add @ApiProperty() and @ApiOperation() throughout your codebase. Also enables client SDK generation (openapi-generator) for typed frontend clients without tRPC.

5.5
Zod — End-to-End Type Safety
Runtime validation that matches your TypeScript types
parallel w/ 5.4

TypeScript's types disappear at runtime. Zod validates data at the boundary (API inputs, env vars, form data) and infers TypeScript types from the schema — one source of truth. Works with tRPC, React Hook Form, and NestJS. Paired with TypeScript, it eliminates an entire class of runtime bugs.

Schema definition (z.object, z.string, z.enum) parse vs safeParse Schema inference (z.infer) Transforms & refinements React Hook Form integration

zod.dev — official docs
Concise reference. Total TypeScript's Zod tutorial is also excellent.

Terraform lets you define your entire infrastructure in HCL files: EC2 instances, S3 buckets, VPC config, DNS records — all in Git, all reproducible, all reviewable. The difference between "I clicked around in the AWS console" and "I have auditable, repeatable infrastructure."

Why learn Java after NestJS?
NestJS gives you Dependency Injection, decorators, modules, and REST APIs. Spring Boot uses the exact same patterns — just verbose Java syntax instead of TypeScript. Your NestJS knowledge cuts Java's learning curve by ~50%. The concepts aren't new; only the ecosystem is.
Why not earlier?
Java before TypeScript/NestJS is painful — Java's verbosity feels arbitrary without a comparison point. After NestJS, you'll immediately understand why every Spring annotation exists. Also: Java without SQL knowledge (Phase 4) means you can't use Spring Data JPA effectively, which is 60% of Spring Boot's value.
Market reality 2026
Java + Spring Boot is still the dominant backend stack in Indian enterprise IT. BFSI (banks, insurance), telecom, government systems — all Java. New greenfield startups prefer Node/Python, but the volume of Java jobs in India dwarfs every other backend language combined. It's a parallel career track, not a replacement.

Is this roadmap enough in 2026+?
An honest, direct answer — what this roadmap does well, what it's missing, and what the AI era actually demands from engineers.
VERDICT
The short answer: Yes, the foundation is correct — but it needs an AI layer on top
The fundamentals are MORE valuable now, not less. But without AI-native skills, you're only half-complete.
important
✓ WHAT HOLDS UP COMPLETELY
  • →Phase 0 (Networking, Git, Shell) — AI can't replace knowing what a TCP packet is or how to debug a broken deployment pipeline at 2AM.
  • →Phase 6 (DevOps/Cloud) — AI doesn't deploy itself. Docker, K8s, Terraform, CI/CD are more critical than ever as AI services need reliable infrastructure.
  • →Phase 7 (DevSecOps) — AI products handle sensitive user data at scale. Security expertise becomes a rare differentiator, not a checkbox.
  • →Databases (Phase 4) — Every AI product needs a data layer. Vector databases are additions to, not replacements for, relational + cache databases.
  • →DSA (continuous) — AI doesn't pass your technical interview. Coding rounds at product companies haven't gotten easier — if anything they've gotten harder as applicant volume grows.
✗ WHAT'S MISSING / NEEDS AUGMENTATION
  • →LLM API Integration — Every product company expects engineers to know how to call OpenAI/Anthropic/Gemini APIs, handle streaming, manage token budgets, and implement retry logic.
  • →RAG Systems — Mentioned in Track D of the AI roadmap but not in this one. Chunking, embedding, vector search, re-ranking — these are now standard backend engineering skills.
  • →Prompt Engineering — Not "prompt hacking" — structured, systematic prompt design for reliable, consistent output. Chain-of-thought, few-shot, system prompts, output parsers.
  • →AI-Native Product Patterns — Streaming UI (SSE), tool/function calling, agent orchestration, fallback chains. These are frontend + backend patterns unique to AI products.
  • →Observability for AI — LLM observability (Langfuse, Braintrust) is a new category. Tracking prompt cost, latency per token, output quality regression — none of this is in Prometheus/Grafana by default.
// THE ACTUAL PICTURE

AI has not eliminated software engineering jobs — it has bifurcated them. There are now two tiers: (1) engineers who understand systems deeply and use AI as a 10x force-multiplier, and (2) people who prompt AI tools without understanding the output. Tier 1 earns more than ever. Tier 2 is being commoditised. This roadmap builds Tier 1 foundations.

What AI has changed: The bar for getting started on a project is lower (AI writes boilerplate). The bar for finishing it correctly, deploying it securely, scaling it, and maintaining it is the same or higher — because now teams are smaller and each person owns more. This roadmap teaches exactly those skills.
